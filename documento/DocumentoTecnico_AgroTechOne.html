1. Visão Geral do Sistema

O Agro Tech One é um sistema web de gestão agrícola desenvolvido com Jakarta EE 10, seguindo o padrão MVC clássico com Servlets, JSP e JDBC manual para PostgreSQL. Esta versão incorpora novos módulos de RH, produção, migração para Bootstrap 5 e correções críticas de bugs.

2.3 Adaptador Gson para LocalDate

Problema: Gson não serializa java.time.LocalDate por padrão, quebrando a resposta JSON. Solução implementada em ControllerFuncionario.java:

private final Gson gson = new GsonBuilder()
    .registerTypeAdapter(LocalDate.class, new JsonSerializer<LocalDate>() {
        @Override
        public JsonElement serialize(LocalDate src, Type typeOfSrc, JsonSerializationContext ctx) {
            return new JsonPrimitive(src.toString()); // retorna "yyyy-MM-dd"
        }
    })
    .create();

2.4 Conversão de Data no Frontend

O datepicker retorna dd/mm/aaaa; o backend espera ISO yyyy-MM-dd. Funções adicionadas em main.js:

function converterDataParaISO(valor) {
  if (!valor) return null;
  if (/^\d{4}-\d{2}-\d{2}$/.test(valor)) return valor;
  const partes = valor.split('/');
  if (partes.length === 3) return partes[2] + '-' + partes[1] + '-' + partes[0];
  return null;
}

function converterDataParaBR(isoDate) {
  if (!isoDate) return '';
  if (typeof isoDate === 'object') {
    // Gson serializa LocalDate como objeto {year, monthValue, dayOfMonth}
    var y = isoDate.year;
    var m = String(isoDate.monthValue).padStart(2, '0');
    var d = String(isoDate.dayOfMonth).padStart(2, '0');
    return d + '/' + m + '/' + y;
  }
  var partes = String(isoDate).split('-');
  if (partes.length === 3) return partes[2] + '/' + partes[1] + '/' + partes[0];
  return isoDate;
}

2.5 Passagem do Context Path para JS externo

JSP EL ${} conflita com template literals JS. Solução: injetar o contexto via variável global no <head>:

<script>window.__ctxPath = '<%=request.getContextPath()%>';</script>

Uso no main.js: (window.__ctxPath || '') + '/ControllerFuncionario'

8. Correções de Bugs
#BugCausa RaizSolução
1 Erro NOT NULL em datanascimentopf ao cadastrar funcionário Datepicker retorna dd/mm/aaaa; LocalDate.parse() exige ISO yyyy-MM-dd Função converterDataParaISO() no JS converte o formato antes do POST
2 Tabela de funcionários não carregava após cadastro bem-sucedido Gson não serializa LocalDate por padrão → JSON quebrado → DataTables recebia null Adicionado adapter JsonSerializer<LocalDate> no GsonBuilder
3 Campo data de nascimento vazio ao abrir modal de edição Bootstrap-datepicker JS não estava carregado em importacao.html; uso incorreto de $.datepicker.parseDate (API jQuery UI) Adicionados CDNs do datepicker em importacao.html; substituído por $('#campo').datepicker('update', valor)
4 Tabela Área de Produção vazia (colunas em branco) Gson serializa pelo nome do campo Java (com maiúscula inicial); JSP lia nomes com minúscula inicial Corrigidos todos os acessos de propriedade no JSP para usar a caixa correta
5 Cabeçalhos de tabela sem estilo verde (.thead-green ausente) Classe CSS utilizada em múltiplas páginas mas nunca definida em estilo.css Adicionado bloco CSS em estilo.css
6 Erro 404 no AJAX de cadastro de funcionário URL hardcoded /agro/FuncionarioServlet (servlet inexistente) Corrigido para (window.__ctxPath || '') + '/ControllerFuncionario'
7 Campos do POST enviados com nomes errados (camelCase vs. lowercase) JS enviava nomePessoa, cpfPf mas controller esperava nomepessoa, cpfpf Padronizados todos os campos do payload JS para lowercase, conforme o controller
8 Modais BS5 não abriam/fechavam Atributos data-toggle/data-dismiss do Bootstrap 4 não funcionam no BS5 Migração global para data-bs-toggle/data-bs-dismiss

11. Instruções de Build e Deploy

11.1 Build Completo

Atenção: O Maven global (mvn) está com problema de configuração neste ambiente. Use sempre o wrapper local. 
# Na pasta raiz do projeto
.\mvnw.cmd clean package

# O WAR é gerado em:
target\agro-1.0-SNAPSHOT.war

11.2 Hot-Copy (sem rebuild — para desenvolvimento)

Copiar arquivos JSP/HTML/JS diretamente para o diretório explodido do Tomcat, sem recompilar:

# Exemplo PowerShell
Copy-Item "src\main\webapp\view\admin\arquivo.jsp" `
          "target\agro-1.0-SNAPSHOT\view\admin\arquivo.jsp" -Force

# O Tomcat detecta a mudança e recarrega automaticamente.
Nota: Hot-copy funciona apenas para arquivos estáticos (JSP, HTML, CSS, JS). Alterações em Java requerem rebuild completo.
